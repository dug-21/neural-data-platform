## Overview

This document defines the exact SQL statements used by the persistence layer. These are parameterized queries executed via DuckDB's PostgreSQL extension against TimescaleDB.

## Table Reference

Target table: `silver.etl_runs`

| Column | Type | Notes |

## INSERT: start_run

### Purpose
Insert a new run record with status='running' at the start of ETL execution.

### SQL Statement

```sql
INSERT INTO pg.silver.etl_runs (
    id,
    stream_id,
    started_at,
    status,
    rows_processed,
    rows_flagged,
    rows_rejected,
    run_mode,
    daemon_cycle_id
) VALUES (
    $1::UUID,          -- id (generated UUID)
    $2,                -- stream_id
    NOW(),             -- started_at (current timestamp)
    'running',         -- status (fixed value)
    0,                 -- rows_processed (initial)
    0,                 -- rows_flagged (initial)
    0,                 -- rows_rejected (initial)
    $3,                -- run_mode ('daemon', 'manual', 'backfill')
    $4::UUID           -- daemon_cycle_id (nullable)
)
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| $1 | UUID | Unique run identifier (generated by caller) |
| $2 | TEXT | Stream ID (e.g., 'air-quality') |
| $3 | TEXT | Run mode ('daemon', 'manual', 'backfill') |
| $4 | UUID (nullable) | Daemon cycle ID (NULL for non-daemon runs) |

### Rust Binding Example

```rust
let run_id = Uuid::new_v4();
let params: [&dyn duckdb::ToSql; 4] = [
    &run_id.to_string(),
    &stream_id,
    &run_mode_str,
    &daemon_cycle_id.map(|id| id.to_string()),
];
conn.execute(sql, params)?;
```

### Notes

- `NOW()` uses DuckDB's timestamp which is UTC
- `::UUID` cast handles string-to-UUID conversion
- `daemon_cycle_id` is NULL for manual/backfill runs

## UPDATE: complete_run

### Purpose
Update a run record on successful completion with final statistics.

### SQL Statement

```sql
UPDATE pg.silver.etl_runs
SET
    completed_at = NOW(),
    duration_ms = $2,
    status = 'success',
    rows_processed = $3,
    rows_flagged = $4,
    rows_rejected = $5,
    watermark_before = $6::TIMESTAMPTZ,
    watermark_after = $7::TIMESTAMPTZ
WHERE id = $1::UUID
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| $1 | UUID | Run ID to update |
| $2 | BIGINT | Duration in milliseconds |
| $3 | BIGINT | Rows processed |
| $4 | BIGINT | Rows with DQ flags |
| $5 | BIGINT | Rows rejected |
| $6 | TIMESTAMPTZ (nullable) | Watermark before ETL |
| $7 | TIMESTAMPTZ (nullable) | Watermark after ETL |

### Rust Binding Example

```rust
let params: [&dyn duckdb::ToSql; 7] = [
    &run_id.to_string(),
    &(stats.duration_ms as i64),
    &(stats.rows_processed as i64),
    &(stats.rows_with_dq_flags as i64),
    &(stats.rows_rejected as i64),
    &stats.watermark_before.map(|dt| dt.to_rfc3339()),
    &stats.watermark_after.map(|dt| dt.to_rfc3339()),
];
let rows_affected = conn.execute(sql, params)?;
if rows_affected == 0 {
    return Err(PersistenceError::RunNotFound(run_id));
}
```

### Notes

- Timestamps are passed as RFC3339 strings, cast to TIMESTAMPTZ
- Returns rows_affected for validation
- First run may have NULL watermark_before

## UPDATE: fail_run

### Purpose
Update a run record on failure with error details.

### SQL Statement

```sql
UPDATE pg.silver.etl_runs
SET
    completed_at = NOW(),
    duration_ms = EXTRACT(EPOCH FROM (NOW() - started_at))::BIGINT * 1000,
    status = 'failed',
    error_message = $2,
    error_context = $3::JSONB
WHERE id = $1::UUID
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| $1 | UUID | Run ID to update |
| $2 | TEXT | Error message (truncated if too long) |
| $3 | JSONB (nullable) | Structured error context |

### Rust Binding Example

```rust
let context_json = error_context
    .map(|ctx| serde_json::to_string(&ctx).unwrap_or_default());

let params: [&dyn duckdb::ToSql; 3] = [
    &run_id.to_string(),
    &truncate_error_message(error_message, 4000),  // Max 4000 chars
    &context_json,
];
conn.execute(sql, params)?;
```

### Notes

- Duration calculated from started_at to now (no need to pass separately)
- error_message should be truncated to prevent oversized records
- error_context allows structured debugging data

## Query: Get Latest Run (for MCP tools)

### Purpose
Get the most recent run for each stream.

### SQL Statement

```sql
SELECT DISTINCT ON (stream_id)
    id,
    stream_id,
    started_at,
    completed_at,
    duration_ms,
    status,
    rows_processed,
    rows_flagged,
    rows_rejected,
    watermark_before,
    watermark_after,
    error_message,
    run_mode
FROM pg.silver.etl_runs
ORDER BY stream_id, started_at DESC
```

## Query: Get Run History (for MCP tools)

### Purpose
Get paginated run history for a specific stream.

### SQL Statement

```sql
SELECT
    id,
    stream_id,
    started_at,
    completed_at,
    duration_ms,
    status,
    rows_processed,
    rows_flagged,
    rows_rejected,
    watermark_before,
    watermark_after,
    error_message,
    error_context,
    run_mode
FROM pg.silver.etl_runs
WHERE stream_id = $1
  AND ($2::TIMESTAMPTZ IS NULL OR started_at > $2)
  AND ($3::TEXT IS NULL OR status = $3)
ORDER BY started_at DESC
LIMIT $4
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| $1 | TEXT | Stream ID (required) |
| $2 | TIMESTAMPTZ | Since timestamp (optional, NULL = all time) |
| $3 | TEXT | Status filter (optional, NULL = all statuses) |
| $4 | INTEGER | Limit (max 100) |

## Query: 24-Hour Summary (for MCP tools)

### Purpose
Get success/failure counts for the last 24 hours per stream.

### SQL Statement

```sql
SELECT
    stream_id,
    COUNT(*) AS total_runs,
    COUNT(*) FILTER (WHERE status = 'success') AS succeeded,
    COUNT(*) FILTER (WHERE status = 'failed') AS failed,
    COUNT(*) FILTER (WHERE status = 'running') AS running
FROM pg.silver.etl_runs
WHERE started_at > NOW() - INTERVAL '24 hours'
GROUP BY stream_id
```

## Query: Cleanup Stale Running Records

### Purpose
Mark runs stuck in 'running' status as failed (orphaned records).

### SQL Statement

```sql
UPDATE pg.silver.etl_runs
SET
    completed_at = NOW(),
    status = 'failed',
    error_message = 'Run marked as failed: exceeded timeout threshold',
    error_context = '{"reason": "stale_running_cleanup"}'::JSONB
WHERE status = 'running'
  AND started_at < NOW() - INTERVAL '1 hour'
```

### Notes

- Run periodically (e.g., every 15 minutes)
- 1 hour threshold accounts for long-running backfills
- Adjust threshold based on expected max ETL duration

---

## Query: Retention Cleanup

### Purpose
Delete old run records to manage storage.

### SQL Statement

```sql
DELETE FROM pg.silver.etl_runs
WHERE created_at < NOW() - INTERVAL '30 days'
```

### Notes

- Run daily via cron or scheduled task
- Uses created_at (not completed_at) for consistent aging
- 30 days provides adequate history for debugging

## DuckDB-Specific Considerations

### 1. PostgreSQL Extension Prefix

All table references use `pg.` prefix because PostgreSQL is attached as `pg`:

```sql
-- Attached as: ATTACH '...' AS pg (TYPE postgres)
-- Therefore:
SELECT * FROM pg.silver.etl_runs  -- Correct
SELECT * FROM silver.etl_runs     -- Wrong (local DuckDB)
```

### 2. TIMESTAMPTZ Casting

DuckDB handles TIMESTAMPTZ differently than PostgreSQL. Always cast:

```sql
-- Pass timestamps as RFC3339 strings
$6::TIMESTAMPTZ   -- Casts string to timestamp
```

### 3. UUID Handling

UUIDs are passed as strings and cast:

```sql
$1::UUID   -- Casts string to UUID type
```

### 4. JSONB Handling

JSONB values are passed as JSON strings:

```sql
$3::JSONB   -- Casts JSON string to JSONB
```

## Parameter Safety

### SQL Injection Prevention

All values use parameterized queries ($1, $2, etc.), never string interpolation:

```rust
// CORRECT: Parameterized
conn.execute(
    "INSERT INTO pg.silver.etl_runs (stream_id) VALUES ($1)",
    [&stream_id]
)?;

// WRONG: String interpolation (vulnerable)
conn.execute(
    &format!("INSERT INTO pg.silver.etl_runs (stream_id) VALUES ('{}')", stream_id),
    []
)?;
```

### Error Message Truncation

Prevent oversized error messages from causing issues:

```rust
fn truncate_error_message(msg: &str, max_len: usize) -> String {
    if msg.len() <= max_len {
        msg.to_string()
    } else {
        format!("{}...[truncated]", &msg[..max_len - 15])
    }
}
```

## Transaction Behavior

### Single-Statement Atomicity

Each operation (INSERT, UPDATE) is a single statement and therefore atomic:

- No explicit `BEGIN`/`COMMIT` needed
- On error, statement rolls back automatically
- Multiple run records are independent (no cross-record transactions)

### Potential Race Conditions

- **start_run**: No conflict (unique UUID generated)
- **complete_run/fail_run**: Single writer per run_id (no conflict)
- **Concurrent cycles**: Different cycle_ids isolate runs
