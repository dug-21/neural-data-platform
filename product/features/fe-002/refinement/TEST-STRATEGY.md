# FE-002: Domain Configuration Standardization - Test Strategy

> **Feature ID:** FE-002
> **Version:** 1.0
> **Created:** 2026-02-05
> **Critical Focus:** Golden Master Testing to GUARANTEE no behavioral change during YAML to JSON migration

---

## Executive Summary

This test strategy defines the **Golden Master Testing** approach that makes it **IMPOSSIBLE** to ship a change that alters DDL output from `ndp-gold-ddl`. The strategy ensures that converting `domain.yaml` to `domain.json` produces byte-for-byte identical DDL output.

**The Critical Guarantee:**
```
BEFORE CHANGES: ndp-gold-ddl generate --domain indoor-air-quality → baseline_ddl.sql (CAPTURED)
AFTER CHANGES:  ndp-gold-ddl generate --domain indoor-air-quality → new_ddl.sql (COMPARED)
VERIFICATION:   diff baseline_ddl.sql new_ddl.sql → MUST BE EMPTY (or fail CI)
```

---

## 1. Golden Master Testing Methodology

### 1.1 What is Golden Master Testing?

Golden Master (also called Characterization or Snapshot Testing) captures the output of a system before changes and compares it against output after changes. Any difference indicates a behavioral change.

**For FE-002, this means:**
- Capture ALL DDL output from `ndp-gold-ddl` BEFORE any code changes
- Store as committed fixtures in the repository
- After migration, regenerate and compare byte-for-byte
- Any difference = automatic test failure = blocked merge

### 1.2 Why Golden Master is Essential for FE-002

| Risk | Without Golden Master | With Golden Master |
|------|----------------------|-------------------|
| Silent behavior change | Undetected until production | Caught immediately in tests |
| JSON parsing edge cases | Could alter SQL structure | Exact SQL comparison catches it |
| Whitespace/formatting differences | May indicate logic changes | Captured and compared |
| Field ordering changes | Could affect SQL generation | Detected by diff |
| Missing optional fields | Could default differently | Existing output preserved |

### 1.3 The Three-Phase Approach

```
┌─────────────────────────────────────────────────────────────────────┐
│                    PHASE 0: BASELINE CAPTURE                        │
│                    (BEFORE ANY CODE CHANGES)                        │
├─────────────────────────────────────────────────────────────────────┤
│  1. Generate all DDL outputs from current YAML config               │
│  2. Store as fixtures in tests/fixtures/golden-master/              │
│  3. Commit to repository                                            │
│  4. Verify fixtures match current behavior (smoke test)             │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    PHASE A: YAML → JSON MIGRATION                   │
│                    (Config format change only)                      │
├─────────────────────────────────────────────────────────────────────┤
│  1. Convert domain.yaml to domain.json                              │
│  2. Update loader.rs to use JSON parser                             │
│  3. Run golden master comparison                                    │
│  4. ONLY proceed if 100% match                                      │
│  5. Any diff = STOP and investigate                                 │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    PHASE B: SCHEMA VALIDATION                       │
│                    (New feature, new tests)                         │
├─────────────────────────────────────────────────────────────────────┤
│  1. Add --domain flag to ndp-validate CLI                           │
│  2. Wire JSON Schema validation                                     │
│  3. Write NEW tests for validation features                         │
│  4. Golden master tests continue passing (no DDL changes)           │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. DDL Output Types to Capture

The `ndp-gold-ddl` tool generates multiple DDL types. **ALL must be captured.**

### 2.1 Domain-Based Outputs (`--domain indoor-air-quality`)

| Output Type | Generated By | SQL Structure |
|-------------|--------------|---------------|
| **Aligned View (sync)** | `AlignedViewGenerator` | `DO $$ ... CREATE MATERIALIZED VIEW gold.indoor_air_quality_aligned AS SELECT ...` |
| **Aligned View (recreate)** | `AlignedViewGenerator` | `DROP ... CASCADE; CREATE MATERIALIZED VIEW ...` |
| **Bucket Index** | `AlignedViewGenerator` | `CREATE INDEX IF NOT EXISTS idx_indoor_air_quality_aligned_bucket ...` |

### 2.2 Stream-Based Outputs (Referenced by Domain)

The domain references these streams, and their DDL affects the aligned view:

| Stream | Output Type | SQL Structure |
|--------|-------------|---------------|

| `outdoor-weather` | Continuous Aggregate | `CREATE MATERIALIZED VIEW gold.outdoor_weather_hourly ...` |
| `outdoor-weather` | Refresh Policy | `SELECT add_continuous_aggregate_policy(...)` |

| `home-assistant-state` | Transitions View | `CREATE MATERIALIZED VIEW gold.home_assistant_state_transitions ...` |
| `outdoor-air-quality` | Continuous Aggregate | `CREATE MATERIALIZED VIEW gold.outdoor_air_quality_hourly ...` |

## 3. Baseline Capture Procedure

### 3.1 CRITICAL: Execute BEFORE Any Code Changes

**Timing is essential.** The baseline MUST be captured from the current working YAML-based system.

### 3.2 Capture Commands

```bash
#!/bin/bash
# Script: scripts/capture-golden-master.sh
# MUST BE RUN BEFORE FE-002 PHASE A STARTS

set -euo pipefail

FIXTURES_DIR="tools/ndp-gold-ddl/tests/fixtures/golden-master"
CONFIG_DIR="./config"

# Create fixture directory
mkdir -p "$FIXTURES_DIR"

echo "=== CAPTURING GOLDEN MASTER BASELINES ==="
echo "Timestamp: $(date -u +%Y-%m-%dT%H:%M:%SZ)"
echo "Git SHA: $(git rev-parse HEAD)"
echo ""

# Capture domain aligned view (sync mode)
echo "Capturing: domain aligned view (sync)..."
cargo run -p ndp-gold-ddl --quiet -- \
    --config-dir "$CONFIG_DIR" \
    generate --domain indoor-air-quality --action sync \
    > "$FIXTURES_DIR/domain_indoor-air-quality_sync.sql"

# Capture domain aligned view (recreate mode)
echo "Capturing: domain aligned view (recreate)..."
cargo run -p ndp-gold-ddl --quiet -- \
    --config-dir "$CONFIG_DIR" \
    generate --domain indoor-air-quality --action recreate \
    > "$FIXTURES_DIR/domain_indoor-air-quality_recreate.sql"

# Capture stream continuous aggregates
for STREAM in air-quality outdoor-weather home-assistant-state outdoor-air-quality; do
    echo "Capturing: stream $STREAM (sync)..."
    cargo run -p ndp-gold-ddl --quiet -- \
        --config-dir "$CONFIG_DIR" \
        generate --stream "$STREAM" --action sync \
        > "$FIXTURES_DIR/stream_${STREAM}_sync.sql" 2>/dev/null || \
        echo "-- Stream $STREAM has no gold_etl config" > "$FIXTURES_DIR/stream_${STREAM}_sync.sql"

    echo "Capturing: stream $STREAM (recreate)..."
    cargo run -p ndp-gold-ddl --quiet -- \
        --config-dir "$CONFIG_DIR" \
        generate --stream "$STREAM" --action recreate \
        > "$FIXTURES_DIR/stream_${STREAM}_recreate.sql" 2>/dev/null || \
        echo "-- Stream $STREAM has no gold_etl config" > "$FIXTURES_DIR/stream_${STREAM}_recreate.sql"
done

# Capture state transitions
echo "Capturing: state transitions..."
cargo run -p ndp-gold-ddl --quiet -- \
    --config-dir "$CONFIG_DIR" \
    generate --stream home-assistant-state --transitions --action sync \
    > "$FIXTURES_DIR/stream_home-assistant-state_transitions_sync.sql" 2>/dev/null || \
    echo "-- No transitions config" > "$FIXTURES_DIR/stream_home-assistant-state_transitions_sync.sql"

cargo run -p ndp-gold-ddl --quiet -- \
    --config-dir "$CONFIG_DIR" \
    generate --stream home-assistant-state --transitions --action recreate \
    > "$FIXTURES_DIR/stream_home-assistant-state_transitions_recreate.sql" 2>/dev/null || \
    echo "-- No transitions config" > "$FIXTURES_DIR/stream_home-assistant-state_transitions_recreate.sql"

# Create manifest of captured files
echo ""
echo "=== CAPTURED FILES ==="
ls -la "$FIXTURES_DIR"/*.sql

# Create checksum manifest
cd "$FIXTURES_DIR"
sha256sum *.sql > CHECKSUMS.sha256
cd - > /dev/null

echo ""
echo "=== CHECKSUMS ==="
cat "$FIXTURES_DIR/CHECKSUMS.sha256"

echo ""
echo "=== BASELINE CAPTURE COMPLETE ==="
echo "Commit these files BEFORE making any code changes."
```

### 3.3 Verify Baseline Integrity

```bash
#!/bin/bash
# Script: scripts/verify-golden-master.sh
# Run after capture to verify fixtures are valid

FIXTURES_DIR="tools/ndp-gold-ddl/tests/fixtures/golden-master"

echo "=== VERIFYING GOLDEN MASTER INTEGRITY ==="

# Check checksums
cd "$FIXTURES_DIR"
sha256sum -c CHECKSUMS.sha256
cd - > /dev/null

# Verify files are not empty (except for missing config cases)
for file in "$FIXTURES_DIR"/*.sql; do
    if [[ $(wc -l < "$file") -lt 2 ]]; then
        if ! grep -q "has no gold_etl" "$file" && ! grep -q "No transitions" "$file"; then
            echo "ERROR: $file appears to be empty or truncated"
            exit 1
        fi
    fi
done

echo "All fixtures verified."
```

## 4. Comparison Procedure

### 4.1 Golden Master Comparison Test

```rust
// Location: tools/ndp-gold-ddl/tests/golden_master_test.rs

use std::fs;
use std::process::Command;

const FIXTURES_DIR: &str = "tests/fixtures/golden-master";

/// Golden Master Test: Domain aligned view (sync mode)
///
/// CRITICAL: This test MUST pass for FE-002 to proceed.
/// Any difference indicates a behavioral change in DDL generation.
#[test]
fn golden_master_domain_indoor_air_quality_sync() {
    // Arrange: Load expected baseline
    let expected = fs::read_to_string(
        format!("{}/domain_indoor-air-quality_sync.sql", FIXTURES_DIR)
    ).expect("Baseline fixture must exist - run capture script first");

    // Act: Generate current output
    let output = Command::new("cargo")
        .args(["run", "-p", "ndp-gold-ddl", "--quiet", "--"])
        .args(["--config-dir", "./config"])
        .args(["generate", "--domain", "indoor-air-quality", "--action", "sync"])
        .output()
        .expect("ndp-gold-ddl must execute");

    let actual = String::from_utf8_lossy(&output.stdout).to_string();

    // Assert: EXACT MATCH required
    assert_eq!(
        expected, actual,
        "\n\n=== GOLDEN MASTER MISMATCH ===\n\
        Domain config migration caused DDL change.\n\
        This indicates a behavioral change that MUST be investigated.\n\n\
        Expected (baseline):\n{}\n\n\
        Actual (current):\n{}\n",
        expected, actual
    );
}
```

### 4.2 Shell-Based Comparison (CI/CD)

```bash
#!/bin/bash
# Script: scripts/compare-golden-master.sh
# Run in CI to verify no DDL changes

set -euo pipefail

FIXTURES_DIR="tools/ndp-gold-ddl/tests/fixtures/golden-master"
TEMP_DIR=$(mktemp -d)
FAILED=0

echo "=== COMPARING GOLDEN MASTER ==="

# Compare domain outputs
for action in sync recreate; do
    echo "Comparing: domain indoor-air-quality ($action)..."

    cargo run -p ndp-gold-ddl --quiet -- \
        --config-dir ./config \
        generate --domain indoor-air-quality --action "$action" \
        > "$TEMP_DIR/domain_indoor-air-quality_${action}.sql"

    if ! diff -q \
        "$FIXTURES_DIR/domain_indoor-air-quality_${action}.sql" \
        "$TEMP_DIR/domain_indoor-air-quality_${action}.sql" \
        > /dev/null 2>&1; then

        echo "MISMATCH DETECTED for domain indoor-air-quality ($action)"
        echo ""
        echo "=== DIFF ==="
        diff -u \
            "$FIXTURES_DIR/domain_indoor-air-quality_${action}.sql" \
            "$TEMP_DIR/domain_indoor-air-quality_${action}.sql" \
            || true
        echo ""
        FAILED=1
    fi
done

# Compare stream outputs
for stream in air-quality outdoor-weather home-assistant-state outdoor-air-quality; do
    for action in sync recreate; do
        echo "Comparing: stream $stream ($action)..."

        cargo run -p ndp-gold-ddl --quiet -- \
            --config-dir ./config \
            generate --stream "$stream" --action "$action" \
            > "$TEMP_DIR/stream_${stream}_${action}.sql" 2>/dev/null || \
            echo "-- Stream $stream has no gold_etl config" > "$TEMP_DIR/stream_${stream}_${action}.sql"

        if ! diff -q \
            "$FIXTURES_DIR/stream_${stream}_${action}.sql" \
            "$TEMP_DIR/stream_${stream}_${action}.sql" \
            > /dev/null 2>&1; then

            echo "MISMATCH DETECTED for stream $stream ($action)"
            diff -u \
                "$FIXTURES_DIR/stream_${stream}_${action}.sql" \
                "$TEMP_DIR/stream_${stream}_${action}.sql" \
                || true
            FAILED=1
        fi
    done
done

# Cleanup
rm -rf "$TEMP_DIR"

if [[ $FAILED -eq 1 ]]; then
    echo ""
    echo "=== GOLDEN MASTER COMPARISON FAILED ==="
    echo "DDL output has changed. This BLOCKS the merge."
    echo ""
    echo "If this is an INTENTIONAL change:"
    echo "  1. Review the diff carefully"
    echo "  2. Update the baseline: ./scripts/capture-golden-master.sh"
    echo "  3. Document the change in the PR description"
    echo ""
    exit 1
fi

echo ""
echo "=== GOLDEN MASTER COMPARISON PASSED ==="
exit 0
```

## 5. Failure Recovery Procedure

### 5.1 When Golden Master Test Fails

```
┌─────────────────────────────────────────────────────────────────────┐
│                    GOLDEN MASTER TEST FAILED                        │
└─────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
           ┌──────────────────────────────────────┐
           │  Is this an INTENTIONAL DDL change?  │
           └──────────────────────────────────────┘
                    │                    │
                   YES                  NO
                    │                    │
                    ▼                    ▼
    ┌───────────────────────┐  ┌───────────────────────┐
    │ 1. Document change    │  │ 1. STOP immediately   │
    │ 2. Update fixtures    │  │ 2. Investigate cause  │
    │ 3. Get PR approval    │  │ 3. Fix the code       │
    │ 4. Re-run tests       │  │ 4. Re-run tests       │
    └───────────────────────┘  └───────────────────────┘
```

### 5.2 Investigation Checklist for Failures

When a golden master test fails, check:

1. **YAML to JSON conversion correctness**
   - Did all fields convert correctly?
   - Are optional fields present/absent as expected?
   - Are arrays in the same order?

2. **Parser differences**
   - Does `serde_json` handle any values differently than `serde_yaml`?
   - Check numeric precision, string escaping, boolean handling

3. **Field ordering in structs**
   - Does JSON field ordering affect iteration order?
   - Check `BTreeMap` vs `HashMap` usage in config types

4. **Whitespace and formatting**
   - Are there any whitespace-sensitive SQL generations?
   - Check for trailing newlines, indentation differences

### 5.3 Recovering from Broken Baseline

If the baseline fixtures are somehow corrupted:

```bash
# 1. Checkout the last known good commit
git checkout HEAD~1 -- tools/ndp-gold-ddl/tests/fixtures/golden-master/

# 2. Verify against that commit
./scripts/verify-golden-master.sh

# 3. If needed, regenerate from a clean state
git stash
./scripts/capture-golden-master.sh
git stash pop
```

## 6. CI/CD Integration

### 6.1 GitHub Actions Workflow

```yaml
# .github/workflows/fe-002-golden-master.yml
name: FE-002 Golden Master Tests

on:
  pull_request:
    paths:
      - 'config/domains/**'
      - 'tools/ndp-gold-ddl/**'
      - 'tools/ndp-validate/**'

jobs:
  golden-master:
    name: Golden Master Comparison
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Rust
        uses: actions-rs/toolchain@v1
        with:
          toolchain: stable
          profile: minimal

      - name: Cache cargo
        uses: actions/cache@v3
        with:
          path: |
            ~/.cargo/registry
            ~/.cargo/git
            target
          key: ${{ runner.os }}-cargo-${{ hashFiles('**/Cargo.lock') }}

      - name: Build ndp-gold-ddl
        run: cargo build -p ndp-gold-ddl --release

      - name: Run Golden Master Comparison
        run: ./scripts/compare-golden-master.sh

      - name: Run Golden Master Rust Tests
        run: cargo test -p ndp-gold-ddl --test golden_master_test -- --nocapture

  # This job MUST pass before merge
  merge-gate:
    name: Merge Gate
    needs: [golden-master]
    runs-on: ubuntu-latest
    steps:
      - name: Verify Golden Master Passed
        run: echo "Golden master tests passed - safe to merge"
```

### 6.2 Branch Protection Rule

Configure GitHub branch protection for `main`:

```yaml

  - Require branches to be up to date before merging: true
```

**CRITICAL**: The golden master check MUST NOT be bypassable.

- No admin override for golden master failures
