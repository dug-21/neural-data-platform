## 1. Silver Tables Metadata

This section documents the four Silver layer TimescaleDB hypertables, their purpose, grain, and source streams.

### 1.1 Table Inventory

| Table Name | Schema | Description | Grain | Source Streams |
|------------|--------|-------------|-------|----------------|
| `air_quality_observations` | silver | Indoor air quality measurements from AirGradient sensors | One row per sensor reading (~1 minute intervals) | air-quality |
| `weather_observations` | silver | Outdoor weather observations from NWS stations and OpenWeatherMap | One row per observation per provider | outdoor-weather, nws-observations |
| `weather_forecasts` | silver | Weather forecasts from NWS gridpoint API with lead time tracking | One row per forecast hour per issue time | nws-gridpoints-forecast |
| `outdoor_air_quality` | silver | Outdoor air quality from OpenWeatherMap Air Pollution API | One row per observation (~10 minute intervals) | outdoor-air-quality |

---

### 1.2 Detailed Table Descriptions

#### 1.2.1 silver.air_quality_observations

| Attribute | Value |
|-----------|-------|
| **Full Name** | `silver.air_quality_observations` |
| **Description** | Indoor air quality measurements from AirGradient sensors, including PM2.5, PM10, CO2, temperature, humidity, and VOC/NOx indices. Primary data source for determining indoor air quality and window-opening decisions. |
| **Grain** | One row per sensor reading per location (~1 minute sampling interval) |
| **Primary Key** | `(observation_time, ndp_id)` |
| **Source Streams** | `air-quality` |
| **Primary Use Case** | Indoor air quality monitoring, window opening/closing recommendations |

**Hypertable Configuration**:
| Setting | Value |
|---------|-------|
| Time Column | `observation_time` |
| Chunk Interval | 1 day |
| Compression | Not enabled (Phase 1) |
| Retention Policy | 365 days |

---

#### 1.2.2 silver.weather_observations

| Attribute | Value |
|-----------|-------|
| **Full Name** | `silver.weather_observations` |
| **Description** | Outdoor weather observations from multiple providers (NWS and OpenWeatherMap), unified into a common schema. Includes temperature, humidity, pressure, wind, visibility, and precipitation. Used for outdoor conditions context when making ventilation decisions. |
| **Grain** | One row per observation per provider (~5-10 minute intervals) |
| **Primary Key** | `(observation_time, ndp_id)` |
| **Source Streams** | `outdoor-weather` (OWM), `nws-observations` (NWS) |
| **Primary Use Case** | Outdoor weather context for indoor/outdoor comparison |

**Hypertable Configuration**:
| Setting | Value |
|---------|-------|
| Time Column | `observation_time` |
| Chunk Interval | 1 day |
| Compression | Not enabled (Phase 1) |
| Retention Policy | 90 days |

**Provider Distinction**:
- `ndp_id = 'weather-owm-002'` for OpenWeatherMap data
- `ndp_id = 'weather-nws-003'` for NWS station data

---

#### 1.2.3 silver.weather_forecasts

| Attribute | Value |
|-----------|-------|
| **Full Name** | `silver.weather_forecasts` |
| **Description** | Weather forecasts from NWS gridpoint API, with dual timestamps for issue time and valid time. Enables forecast accuracy analysis by tracking lead_time_hours. Includes temperature, wind, precipitation probability, humidity, and sky cover forecasts. |
| **Grain** | One row per forecast hour per issue time |
| **Primary Key** | `(issue_time, valid_time, ndp_id)` |
| **Source Streams** | `nws-gridpoints-forecast` |
| **Primary Use Case** | Forecast accuracy tracking, predictive ventilation scheduling |

**Hypertable Configuration**:
| Setting | Value |
|---------|-------|
| Time Column | `valid_time` |
| Chunk Interval | 1 day |
| Compression | Not enabled (Phase 1) |
| Retention Policy | 30 days |

**Forecast Domain Model**:
- `issue_time`: When the forecast was generated by NWS
- `valid_time`: When the forecast applies (future timestamp)
- `lead_time_hours`: Computed as `EXTRACT(EPOCH FROM (valid_time - issue_time)) / 3600`

---

#### 1.2.4 silver.outdoor_air_quality

| Attribute | Value |
|-----------|-------|
| **Full Name** | `silver.outdoor_air_quality` |
| **Description** | Outdoor air quality measurements from OpenWeatherMap Air Pollution API. Includes AQI (both OWM 1-5 scale and EPA 0-500 scale), PM2.5, PM10, and gas concentrations (CO, NO, NO2, O3, SO2, NH3). Critical for comparing indoor vs outdoor air quality. |
| **Grain** | One row per observation (~10 minute polling interval) |
| **Primary Key** | `(observation_time, ndp_id)` |
| **Source Streams** | `outdoor-air-quality` |
| **Primary Use Case** | Indoor/outdoor AQ comparison, ventilation decision support |

**Hypertable Configuration**:
| Setting | Value |
|---------|-------|
| Time Column | `observation_time` |
| Chunk Interval | 1 day |
| Compression | Not enabled (Phase 1) |
| Retention Policy | 90 days |

| `o3_ugm3` | DOUBLE PRECISION | ug/m3 | Ozone concentration | YES | 11 |
| `so2_ugm3` | DOUBLE PRECISION | ug/m3 | Sulfur dioxide concentration | YES | 12 |
| `nh3_ugm3` | DOUBLE PRECISION | ug/m3 | Ammonia concentration | YES | 13 |
| `dq_flags` | TEXT[] | - | Data quality flags array | YES | 14 |

**Indexes**:
- GIN index on `dq_flags` for DQ analysis queries
- BTREE index on `(ndp_id, observation_time DESC)` for time-series queries

**Computed Column (aqi_epa)**:
```sql
aqi_epa = CASE aqi_owm
    WHEN 1 THEN 25   -- Good (0-50 EPA range midpoint)
    WHEN 2 THEN 75   -- Moderate (51-100 EPA range midpoint)
    WHEN 3 THEN 125  -- Unhealthy for Sensitive Groups (101-150)
    WHEN 4 THEN 175  -- Unhealthy (151-200)
    WHEN 5 THEN 300  -- Very Unhealthy/Hazardous (201-500)
    ELSE NULL
END
```

### 3.6 Transformation Reference

| Transformation Name | Formula | Description |
|---------------------|---------|-------------|
| `direct` | `value` | No transformation, value passed through |
| `microseconds_to_timestamp` | `to_timestamp(value / 1000000)` | Bronze microsecond epoch to TIMESTAMPTZ |
| `hpa_to_pa` | `value * 100` | Hectopascals to Pascals |
| `m_s_to_km_h` | `value * 3.6` | Meters per second to kilometers per hour |
| `nws_duration` | ISO8601 duration parse | NWS validTime duration to timestamp |
| `owm_to_epa_aqi` | CASE expression | OpenWeatherMap 1-5 scale to EPA 0-500 scale |

## 4. Query Examples

This section provides example queries users can run against the data dictionary to discover Silver layer metadata.

### 4.1 Table Discovery Queries

**"What Silver tables exist?"**
```sql
SELECT
    table_name,
    description,
    grain,
    source_streams,
    hypertable_column,
    chunk_interval
FROM data_dictionary.silver_tables
ORDER BY table_name;
```

**Expected Result**:
| table_name | description | grain | source_streams | hypertable_column | chunk_interval |
|------------|-------------|-------|----------------|-------------------|----------------|
| air_quality_observations | Indoor air quality... | One row per sensor reading | {air-quality} | observation_time | 1 day |
| outdoor_air_quality | Outdoor air quality... | One row per observation | {outdoor-air-quality} | observation_time | 1 day |
| weather_forecasts | Weather forecasts... | One row per forecast hour | {nws-gridpoints-forecast} | valid_time | 1 day |
| weather_observations | Outdoor weather... | One row per observation | {outdoor-weather,nws-observations} | observation_time | 1 day |

## 5. Config Extension Proposal

This section proposes backward-compatible extensions to the `silver_etl` field_mappings configuration to support the data dictionary.

### 5.1 Current Config Structure

```yaml
silver_etl:
  enabled: true
  target_table: silver.air_quality_observations
  field_mappings:
    - source_path: raw_payload.pm02Compensated
      target_column: pm25
      type: double_precision
      nullable: false
      dq_rules:
        - rule: range_check
          min: 0.0
          max: 1000.0
          action: flag
```

### 5.2 Proposed Extensions

Add two new optional fields to each field_mapping:

| New Field | Type | Required | Description |
|-----------|------|----------|-------------|
| `unit` | string | No | SI unit or measurement scale (e.g., "ug/m3", "Celsius", "%") |
| `description` | string | No | Human-readable description for data dictionary |

Add two new optional fields to the `silver_etl` block:

| New Field | Type | Required | Description |
|-----------|------|----------|-------------|
| `description` | string | No | Human-readable description of the Silver table |
| `grain` | string | No | Definition of table grain (one row per...) |

### 5.3 Extended Config Example

```yaml
silver_etl:
  enabled: true
  target_table: silver.air_quality_observations
  description: "Indoor air quality measurements from AirGradient sensors"
  grain: "One row per sensor reading (~1 minute intervals)"

  field_mappings:
    - source_path: raw_payload.pm02Compensated
      target_column: pm25
      type: double_precision
      unit: "ug/m3"
      description: "PM2.5 particulate matter concentration (humidity-compensated)"
      nullable: false
      dq_rules:
        - rule: range_check
          min: 0.0
          max: 1000.0
          action: flag

    - source_path: raw_payload.atmpCompensated
      target_column: temperature_c
      type: double_precision
      unit: "Celsius"
      description: "Ambient temperature from sensor (compensated for heat generation)"
      nullable: true
      dq_rules:
        - rule: range_check
          min: -40.0
          max: 85.0
          action: flag

    - source_path: raw_payload.rhumCompensated
      target_column: humidity_pct
      type: double_precision
      unit: "%"
      description: "Relative humidity (compensated)"
      nullable: true
      dq_rules:
        - rule: range_check
          min: 0.0
          max: 100.0
          action: clamp
          clamp_to_bounds: true
```

### 5.4 Backward Compatibility

- All new fields are **optional** - existing configs continue to work
- Missing `unit` defaults to `NULL` in data dictionary
- Missing `description` defaults to `NULL` in data dictionary
- Sync script handles missing fields gracefully
